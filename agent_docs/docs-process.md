## Repo-Specific Rules

- Keep docs role-specific and easy to scan.
- Do not turn standards docs into archives.
- Keep `todo.md` as current task tracking, not a long narrative log.
- Keep role playbooks durable: append genuinely useful recurring guidance, and remove stale or duplicated rules.

## High-Value Context

- `agent_docs/plans.md` is the planning standard, not a task history file.
- `agent_docs/codex.md` is repo memory for breakages and safe patterns, not a generic guide.
- Specialist playbooks should contain durable role knowledge, not transient task notes.

## Anti-Patterns

- Letting completed-task history accumulate in standards docs.
- Copying the same guidance into multiple docs without deciding which file owns it.
- Leaving stale process instructions behind after the workflow changes.

## Verification Expectations

- Re-read changed docs for contradictions and stale references
- Confirm file lists and commands still match the repo
- If task numbering changes in `todo.md`, keep the remaining tasks renumbered and the completed summaries concise
